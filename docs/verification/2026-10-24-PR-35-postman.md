## Defect found and corrected

The first expanded run failed Pasalo rejection: HTTP 500, SQLSTATE `22001`,
"value too long for type character varying(10)". `disapproved` has 11 characters,
but `booking_players.status` allowed only 10. `db/schema.sql` now uses
`VARCHAR(11)`, preserving its existing CHECK constraint and API vocabulary
(FR-08). The same rejection and persisted outgoing-status assertions pass on
the corrected fresh schema. Existing initialized databases need the agreed
schema-update process; no existing database was directly altered or reset.

## Environment and practical limits

The default Compose start encountered occupied ports: an earlier
`pickle-rick-defects` stack already served localhost:4000. The initial run
exercised that older stack and its API cleanup completed, but default-project
SQL cleanup failed because that project's Postgres was not running. Final
verification used a new isolated `pickle-rick-pr35` backend/Postgres project
on ports 4035/55435, with attached logs, a fresh volume and corrected schema:

```powershell
# Root, first terminal; override is a local verification artifact, not committed.
docker compose -p pickle-rick-pr35 -f docker-compose.yml -f testing/postman/newman/verify.compose.yml up --build postgres backend-node

# testing/postman, second terminal
$env:COMPOSE_PROJECT_NAME = 'pickle-rick-pr35'
$env:POSTMAN_BASE_URL = 'http://localhost:4035'
npm test
```

The override replaces Postgres port mappings with `55435:5432` and backend
mappings with `4035:4000`. No existing volumes were removed and no user-data
reset occurred. The earlier stack was preserved.

Postman desktop import/GUI execution was not tested. Its cleanup folder removes
database records but cannot delete server photo files; automatic photo-file
cleanup requires the npm wrapper. Ctrl+C/hard termination can bypass finally;
standalone recovery is documented. Sequential cap tests do not prove concurrent
Pasalo safety. The unresolved multiple-pending-manual-booking policy was not
changed. No new purchasing/analytics routes or API versioning were implemented.
GitHub QA/Main gates and merge remain separate from local verification.
