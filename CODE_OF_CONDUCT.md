# Code of Conduct

Welcome to my personal project - Pickle Rick, a Pickleball Court Management and Reservation System.

This space represents my professional work and knowledge in Full-Stack Development, DevOps, and QA Testing. It's a learning project and GitHub portfolio piece, not an open community project - but it should still be a respectful, professional space for anyone who reads, forks, or comments on it. It also serves as a living record of my ongoing journey in Node.js/Python full-stack development, raw SQL, Dockerized environments, CI/CD pipelines, and QA automation. Future updates will highlight my progress on the remaining roadmap items (see [docs/roadmap.md](docs/roadmap.md)), ensuring this project reflects both my current skills and my commitment to continuous learning.

All interactions here should remain respectful, professional, and constructive.

## Principles
- Communicate with respect and courtesy.
- Provide feedback that is helpful and relevant.
- Avoid discriminatory or offensive behavior.
- Follow ethical and legal standards in any shared code or contributions.
- Respect the security and privacy expectations of a system that handles real account credentials and booking data, even in a local/demo context.

## Continuous Learning & Future Plans
This project is not only a reflection of my current skills but also a platform for growth. I plan to expand my knowledge and apply best practices in areas such as:
- Completing the purchasing/checkout flow (Player-side shop against a court's inventory).
- Building out `analytics-service-python` for revenue/profit reporting.
- Widening Postman, k6, and Playwright test coverage beyond the Auth module.
- Structured logging, security hardening (`helmet`, rate limiting), and other production-grade conventions tracked in `docs/claude-instructions.md`.
- Future updates will integrate these practices, ensuring Pickle Rick evolves into a robust, well-tested, and production-minded system.

## Security & Data Commitment
This project aims to be secure enough to be published publicly on GitHub with no security or privacy issues (see NFR-03 in the [Software Requirements Specification](docs/software-requirements-specification.md)) - no committed secrets, no unsafe handling of credentials, and no shortcuts that would put real user data at risk if this pattern were reused elsewhere.

## Enforcement
Any violation of these guidelines may result in restricted access or removal of interactions from this repository.

Thank you for maintaining a professional and respectful environment.
